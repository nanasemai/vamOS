# development-workflow 规范

## 目的
定义 vamOS 项目的开发工作流程和最佳实践。

## 需求
### 需求：上游同步
开发分支应与 upstream/master 保持合理同步，以确保兼容性并减少合并冲突。

#### 场景：定期上游同步
- **当**上游有重大更改（落后 >20 个提交）时
- **那么**应在新的开发工作之前执行同步操作

#### 场景：同步验证
- **当**完成上游同步时
- **那么**所有现有的自定义代码和 openspec 更改保持功能正常

### 需求：代码审查流程
所有代码更改必须经过代码审查才能合并到主分支。

#### 场景：PR 需要审查
- **给定**提交的 pull request
- **当**审查者批准后
- **那么**PR 才能被合并

#### 场景：自动化检查通过
- **给定**提交的 pull request
- **当**所有 CI 检查通过时
- **那么**PR 才能被合并
